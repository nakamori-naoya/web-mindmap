# 初期版の受入試験記録

ローカルでの日本語編集、SQLite保存と再読込、全体画像出力、バックアップからの復元を自動試験で確認した。実機の日本語変換、OS・ブラウザの差などは未確認部分があるため、全18項目を完全合格とする記録ではない。利用者と受入担当者が、確認済みの範囲と残る手動確認を判断するための資料である。

## 自動試験と実行環境

2026年11月8日に型検査、本番ビルド、ドメイン・配置・入出力・SQLite・HTTP APIの22試験が成功した。実ChromeのPlaywright E2Eは29試験成功し、日本語階層編集、IMEイベント、保存失敗、ドラッグとUndo、JSON往復、PNG/SVG出力、検索、テーマ、メモ・リンク・書式のUndo、文字数上限、右クリック、キーボード操作、空本文の境界を確認した。全体11試験成功後、ドラッグ試験を69%表示のズーム後操作に拡張し、本番ビルドと当該1試験も成功した。アプリのソース変更は必要なかった。

測定ホストはApple M5 Pro・64GB、darwin 25.6 arm64、Node.js 26.13.0。ブラウザはheadless Chrome 157.0.8103.38、1440×1000、ローカルVite開発サーバーで測った。DockerはローカルOrbStackのUnixソケットを使用し、専用の一時DBで正常再起動、SIGKILL後の再起動、SQLiteバックアップと実リストアを検証した。

実行対象は /path/to/web-mindmap/tests/domain.test.ts、/path/to/web-mindmap/tests/layout.test.ts、/path/to/web-mindmap/tests/io.test.ts、/path/to/web-mindmap/tests/storage.test.ts、/path/to/web-mindmap/tests/api.test.ts、/path/to/web-mindmap/tests/e2e/editor.spec.ts、/path/to/web-mindmap/tests/e2e/performance.spec.ts である。Compose実検証の記録は /path/to/web-mindmap/docs/compose-verification.json に残した。

**A09は実施済み。** SQLiteのバックアップAPIで稼働中のDBを保全し、サーバー停止、現状DB退避、復元、整合性検査、再起動を実行した。全マップ、本文、メモ、書式、子の順序が復元元と一致した。ホストCLIと独立Compose環境の両方で実リストアを確認した。起動中のサーバーと復元処理の同時実行は別のSQLite排他で拒否した。

**A10は実施済み。** JSON出力と読込で本文、順序、メモ、書式、表示状態を保持する単体試験と、プレビューを経て新規マップへ取り込むE2Eが成功した。新規読込ではIDを再生成し、既存文書を置き換えない。

**A11は実施済み。** 破損JSON、重複キー、循環、不整合な親子、到達不能ノード、不正ID、未知の形式版、上限超過ファイルを拒否した。HTTPでも不正JSONと未知版を拒否し、10MBを超える本文に413を返した。不正保存後も現在版と復旧候補は変わらなかった。

## 性能は測定した操作では目標内だった

1000ノード・深さ10のブラウザ計測は、初回表示198.7ms、追加から二回のrequestAnimationFrameまでのp95が40.7ms（20回）、パンのフレーム間隔p95が16.7ms（69標本）、ドラッグが16.8ms（125標本）だった。表示にはPlaywrightの待機も含む。パンとドラッグはPlaywrightのmouse入力で測定しており、物理トラックパッドの測定ではない。5000ノードはAPI保存と表示が成功した。

純粋な配置計算は、1000ノード・深さ10・平均39.964文字、50回で初回5.291ms、中央値3.762ms、p95 5.043msだった。5000ノード・深さ13では初回18.606ms、中央値18.887ms、p95 23.102ms。これはDOM描画を含まないため、ブラウザ全体の表示時間とは区別する。

生のブラウザ測定値と測定条件は /path/to/web-mindmap/docs/browser-performance.json に保存している。いずれもこのホストとブラウザでの観測値であり、8GBの端末、Chromeの前版、WindowsのChrome/Edge、スマートフォンで同じ性能を保証しない。

## レビューで見つかった不具合の再検証

独立レビューで採用した6指摘は、メモ入力中の保存、メモUndo後の表示、2001文字の編集中ドラフト保護、右クリックメニュー、SIGKILL後の再起動、リンクUndo後の表示である。修正後、レビュー担当が元の再現手順で確認し、6件とも再現しなくなったとして取り下げた。メモは再読込後も保持し、Undoは表示と文書が一致した。上限超過時はドラフトを保持して追加せず、右クリックは編集へ移らずメニューを開いた。リンクUndoは表示が空、リンクアイコン0、保存文書のlinkが未指定で一致した。

追加の実装点検で見つかった空の新規ノード確定も、既定名の確定、新規取消、再読込をE2Eに追加して確認した。独立レビューでは、新規作成時の画面遷移後も編集が続くこと、同一マップのURL更新で既存ドラフトと空の新規ノードが残ること、保存後の再読込で文書JSONが一致することも確認した。これらの試験結果は、物理IME、Chrome前版、Windows/Edgeなど未実施の試験を代替しない。

## 編集中の見え方とアウトライン操作を独立再評価した

編集中の本文に合わせて配置と入力欄を更新し、日本語5行を確定前に表示する。2000文字の本文は画面内に収まる複数行の入力領域で内部スクロールできる。実装担当の回帰試験に加え、独立評価担当が1440px幅と390px幅で、複数行表示、上下キーによるキャレット移動、合成IME中の編集継続を確認した。物理IMEでの確認は未実施である。

アウトライン内で子と兄弟を追加し、その場で本文を編集できる。Tabは子、Enterは兄弟、Spaceは本文編集に使う。Undo/Redoと保存後の再読込で文書を保持した。中心本文の末尾欠け、Spaceリピート後の意図しない編集、再読込後の枝貼付失敗、入力済み新規ノードの取消は、元の再現手順で症状が出なくなった。

リンク入力中の保存、未完成URLの離脱保護、マップ名の置換、一覧からの読込直後の配置、保存成功後の警告解消、復旧モーダル内のエラーと候補のメモ表示、検索の最初の結果を独立再評価した。狭い画面は書式パネルを初期非表示とし、アウトラインと同時に図を覆わない。操作領域と色パレットの折返しも回帰試験で確認した。

統合した最終状態の型検査・本番ビルド・Unit/API22試験・Chrome29試験が成功した。性能試験は追加後に画面外へ移った中心をクリックし続けず、内向き矢印と「選択へ移動」で親へ戻る通常操作を使って計測した。この移動時間は追加反映の計測に含めない。最新値と条件は docs/browser-performance.json を参照する。

## 画像機能統合後の最終確認

2026年11月8日、画像機能の修正を統合した状態で本番ビルドが成功し、Unit/API38試験、Chrome35試験が成功した。Chrome35試験の実行時間は54.5秒だった。最終統合の実行主体はマネージャーであり、この操作別資料の作成担当は試験を再実行していない。

画像に関する独立レビューで採用した指摘は、最後の画像を外した後のJSON再取込、有効なアニメーションPNGの無警告な静止画化、実行用コンテナの参照先モジュール欠落だった。修正後は、元の手順で画像ゼロのJSON往復、アニメーション拒否、実行用コンテナの起動と稼働確認に成功し、3指摘とも取り下げられた。

利用中の保存先とは別のCompose環境で、画像の保存、再起動後の再表示、画像BLOBを含むバックアップと復元が成功した。ネットワークを持たず、実利用データを使わないコンテナでも起動と稼働確認が成功した。画像の取り込み・削除とUndo・画像付きJSON・SVG・PNG・別マップへの画像付き枝コピーは自動試験の対象である。

物理IME、実タッチ端末、Windows/Edge、画像の高並列処理時のメモリ量、保持量合計64MiBへの実到達、網羅的な画像fuzzは未確認である。個別ファイルで定める、これ以外の未確認境界も自動で合格へ変更しない。条件の定義は[ユーザー操作別の受け入れ条件](acceptance.md)を参照する。
