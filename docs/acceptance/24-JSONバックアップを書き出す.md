# マップをJSONバックアップへ書き出す

本文・順序・書式・メモ・画像を持ち運べる一つのバックアップを保存できる。この結果を利用者が画面、再読込、または保存したファイルから確認できることを受け入れ条件とする。

## 操作前の状態

保存済みの画像付きマップと、最後の画像を外したマップを用意している。アプリは本人1人のローカル環境で動作し、同じマップは一つの編集画面で扱う。

## ユーザーの操作

1. 書き出しからJSONを選ぶかCmd/Ctrl+Sを押す。
2. 画像付きと画像ゼロのマップで、それぞれファイルを保存する。
3. 別の新規マップとして読み込み、内容を比較する。

## 期待する結果

- 本文・順序・書式・メモ・リンク・表示状態を保つ。
- 使用中の画像をファイル内に含め、元のローカルパスを必要としない。
- 画像ゼロになった文書も有効なJSONとなり、新規読込で失敗しない。

## 失敗・取消・境界で守ること

- 画像取り込み中や本文確定エラーがある場合、途中状態を成功として出力しない。
- 画像本体の取得に失敗した場合、画像を欠かしたファイルを完成扱いにしない。
- 過去版だけが使う画像は現在マップのJSONへ含めず、SQLiteバックアップとは保存範囲を区別する。

## 確認方法と現在の状態

JSON往復、画像同梱、元ファイル名不在を確認する試験がある。画像ゼロのJSON往復も独立再確認済みである。対応する試験は[e2e/editor.spec.ts](../../tests/e2e/editor.spec.ts)、[e2e/node-images.spec.ts](../../tests/e2e/node-images.spec.ts)、[images-domain.test.ts](../../tests/images-domain.test.ts)、[images-api.test.ts](../../tests/images-api.test.ts)にある。統合後の本番ビルド、Unit/API38試験、Chrome35試験は成功した。以下の未確認範囲を含め、すべての受け入れ条件が合格したと扱うものではない。

100MiB付近の実ブラウザダウンロードと、通信断との全組合せは未測定。試験定義があることを、このファイルの全条件が合格したという意味にはしない。実行日時と結果は[検証記録](../verification-results.md)へ残す。
