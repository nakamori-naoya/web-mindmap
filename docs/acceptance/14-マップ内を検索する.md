# 本文を検索し、一致した枝へ移動する

結果番号と実際の選択を一致させ、隠れた枝も検索から見つけられる。この結果を利用者が画面、再読込、または保存したファイルから確認できることを受け入れ条件とする。

## 操作前の状態

「資料A」「資料B」を含み、一部が折り畳まれたマップを開いている。アプリは本人1人のローカル環境で動作し、同じマップは一つの編集画面で扱う。

## ユーザーの操作

1. 検索ボタンまたはCmd/Ctrl+Fで検索欄を開く。
2. 「資料」と入力し、Enterと次・前の検索結果ボタンを使う。
3. 一致しない語へ変え、検索を閉じる。

## 期待する結果

- 最初のEnterで最初の一致結果を選び、表示番号と選択が一致する。
- 次・前で結果を巡回し、隠れた枝は必要な祖先を展開して見える位置へ移す。
- 結果がない場合はその状態を表示し、既存の本文を変更しない。

## 失敗・取消・境界で守ること

- 入力欄での検索語編集をノードの文字編集や追加として処理しない。
- 検索を閉じた後、通常のマップ操作へ戻れる。

最初のEnter、結果移動、検索を含む入出力操作の試験がある。対応する試験は[e2e/workflow-ux.spec.ts](../../tests/e2e/workflow-ux.spec.ts)、[e2e/editor.spec.ts](../../tests/e2e/editor.spec.ts)にある。統合後の本番ビルド、Unit/API38試験、Chrome35試験は成功した。以下の未確認範囲を含め、すべての受け入れ条件が合格したと扱うものではない。
