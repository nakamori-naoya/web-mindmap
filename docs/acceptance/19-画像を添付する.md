# 画像を選択・貼り付け・ドロップで添付する

取り込んだ画像を元ファイルの場所に依存せず、狙ったトピックへ表示・保存できる。この結果を利用者が画面、再読込、または保存したファイルから確認できることを受け入れ条件とする。

## 操作前の状態

画像を付けたいトピックを一つ選択し、合成の静止PNG・JPEG・WebPを用意する。アプリは本人1人のローカル環境で動作し、同じマップは一つの編集画面で扱う。

## ユーザーの操作

1. 画像の選択ボタン、ノードへのファイルドロップ、画像クリップボードの貼り付けを別々に実行する。
2. 取り込みと保存が終わるまで待ち、元ファイルを別の場所へ移してからページを再読込する。
3. 取り込みを遅延させ、途中で別ノードを選ぶ試行と一覧へ移ろうとする試行を行う。

## 期待する結果

- 本文の下に縦横比を保った画像を表示し、本文や隣の枝を覆わない。
- 元ファイルの移動・削除後も画像を表示し、保存内容に元パス・元ファイル名・外部参照URLを残さない。
- 取り込み中と失敗理由を画面に示す。選択が変わっても開始時のノードへ添付し、取り込み中の画面離脱を保護する。
- 本文編集中の通常の文字貼り付けを、画像貼り付け操作が妨げない。

## 失敗・取消・境界で守ること

- 1枚10MiB・2500万画素までの静止PNG/JPEG/WebPを受け付け、1ノード8枚を上限とする。
- SVG、偽装、破損、アニメーションPNG/WebPなどを拒否し、先頭フレームだけを無言で残さない。
- 画像の向きを補正し、位置情報などのメタデータを除き、長辺2048px以下・保存8MiB以内に正規化する。
- 1マップの保持上限200枚・合計64MiBを超える追加は、元の内容を壊さず理由を表示する。取り外した画像も保持量へ数える。

## 確認方法と現在の状態

取込方法、遅延時の添付先、再読込、不正拒否、正規化、200枚上限の試験がある。有効な2フレームAPNGの拒否も修正後に独立再確認され、指摘が取り下げられた。対応する試験は[e2e/node-images.spec.ts](../../tests/e2e/node-images.spec.ts)、[images-api.test.ts](../../tests/images-api.test.ts)、[images-domain.test.ts](../../tests/images-domain.test.ts)にある。統合後の本番ビルド、Unit/API38試験、Chrome35試験は成功した。以下の未確認範囲を含め、すべての受け入れ条件が合格したと扱うものではない。

実OSの全クリップボード形式、合計64MiB実到達、高並列取り込み時のメモリ量は未測定。試験定義があることを、このファイルの全条件が合格したという意味にはしない。実行日時と結果は[検証記録](../verification-results.md)へ残す。
