# 保存済みの候補を選んで復旧する

目的の保存版を見分け、確認して本文・メモ・画像をまとめて戻せる。この結果を利用者が画面、再読込、または保存したファイルから確認できることを受け入れ条件とする。

## 操作前の状態

メモや画像が異なる複数の保存版があるマップを開いている。アプリは本人1人のローカル環境で動作し、同じマップは一つの編集画面で扱う。

## ユーザーの操作

1. 「復旧」を開き、候補を切り替えてプレビューする。
2. 戻したい候補を選び、「この内容へ復旧」を押して確認する。
3. 専用環境で復旧を失敗させる試行も行う。

## 期待する結果

- 直近5世代の候補を選べ、同じ分に保存しても識別情報と本文・メモ・リンクなどを確認できる。
- 選んだ保存版の本文・順序・書式・メモ・画像を戻し、再読込しても一致する。
- 失敗理由は復旧ダイアログ内に表示し、暗転した背面だけに出さない。

## 失敗・取消・境界で守ること

- 未完成の名前・リンクや未保存内容を黙って捨てて復旧へ進まない。
- 現在ノードから画像を外していても、画像付きの過去版は画像ごと復旧できる。
- 確認を取り消した場合は、現在の内容を変えない。

## 確認方法と現在の状態

候補メモ表示、ダイアログ内エラー、保存版画像の再参照を確認する試験がある。対応する試験は[e2e/workflow-ux.spec.ts](../../tests/e2e/workflow-ux.spec.ts)、[storage.test.ts](../../tests/storage.test.ts)、[images-api.test.ts](../../tests/images-api.test.ts)にある。統合後の本番ビルド、Unit/API38試験、Chrome35試験は成功した。以下の未確認範囲を含め、すべての受け入れ条件が合格したと扱うものではない。

5世代境界と画像の組合せを実画面で全件確認したものではない。試験定義があることを、このファイルの全条件が合格したという意味にはしない。実行日時と結果は[検証記録](../verification-results.md)へ残す。
