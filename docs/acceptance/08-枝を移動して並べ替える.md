# 枝の親を変え、兄弟を並べ替える

移動先を見ながら配下ごと枝を移し、一回のUndoで元へ戻せる。この結果を利用者が画面、再読込、または保存したファイルから確認できることを受け入れ条件とする。

## 操作前の状態

少なくとも二つの主枝と、子孫を持つ移動元の枝を用意している。アプリは本人1人のローカル環境で動作し、同じマップは一つの編集画面で扱う。

## ユーザーの操作

1. 枝を5px以上ドラッグし、別の親の候補枠または兄弟の間の挿入線を確認する。
2. 候補へドロップし、親と順序、配下の本文・画像を確認する。
3. Undoを一回実行する。

## 期待する結果

- 親変更では配下全体を保持し、並べ替えでは指定位置へ一度だけ移る。
- ドラッグ中に候補と元位置を識別でき、ズーム後もポインターと狙う位置がずれない。
- 一回のUndoで親、順序、配下の内容が元へ戻る。

## 失敗・取消・境界で守ること

- 自身または子孫への移動、中心の親変更は成立せず元データを保持する。
- Escapeまたは空白へのドロップで取り消し、独立した枝を勝手に作らない。
- 折り畳んだ枝を移しても、非表示の配下を失わない。

## 確認方法と現在の状態

ズーム後の親変更とUndo、循環拒否、深い配下保持、固定乱数500操作の試験がある。対応する試験は[e2e/editor.spec.ts](../../tests/e2e/editor.spec.ts)、[domain.test.ts](../../tests/domain.test.ts)、[layout.test.ts](../../tests/layout.test.ts)にある。統合後の本番ビルド、Unit/API38試験、Chrome35試験は成功した。以下の未確認範囲を含め、すべての受け入れ条件が合格したと扱うものではない。

画像付き大枝の端自動スクロール、タッチでの高度なドラッグは未確認。試験定義があることを、このファイルの全条件が合格したという意味にはしない。実行日時と結果は[検証記録](../verification-results.md)へ残す。
