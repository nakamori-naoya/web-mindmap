# 保存失敗を確認し、再試行する

失敗中の編集内容を保ち、再試行成功後の画面と保存内容を一致させる。この結果を利用者が画面、再読込、または保存したファイルから確認できることを受け入れ条件とする。

## 操作前の状態

通信失敗を再現する専用マップでメモまたは本文を変更する。実利用データは使わない。アプリは本人1人のローカル環境で動作し、同じマップは一つの編集画面で扱う。

## ユーザーの操作

1. 保存要求だけを失敗させる。
2. 一覧へ戻ろうとし、残っている編集内容と警告を確認する。
3. 通信を戻し、「保存を再試行」を押してから再読込する。

## 期待する結果

- 未保存と再試行手段を表示し、保存済みと誤表示しない。
- 画面移動を止め、入力した内容を失わない。必要ならJSONで退避できる。
- 再試行成功後は内容が保存され、未保存警告も消える。

## 失敗・取消・境界で守ること

- 容量不足やサーバー停止でも、成功したように見せない。
- JSON退避に必要な画像が取得できない場合は、画像を欠いた成功ファイルを黙って出力しない。

## 確認方法と現在の状態

PUT失敗と一覧保護、再試行後の警告解消、バックアップ先障害を確認する試験がある。対応する試験は[e2e/workflow-ux.spec.ts](../../tests/e2e/workflow-ux.spec.ts)、[e2e/editor.spec.ts](../../tests/e2e/editor.spec.ts)、[storage.test.ts](../../tests/storage.test.ts)にある。統合後の本番ビルド、Unit/API38試験、Chrome35試験は成功した。以下の未確認範囲を含め、すべての受け入れ条件が合格したと扱うものではない。

ディスク容量の実枯渇と画像取得失敗を重ねた全画面経路は未網羅。試験定義があることを、このファイルの全条件が合格したという意味にはしない。実行日時と結果は[検証記録](../verification-results.md)へ残す。
