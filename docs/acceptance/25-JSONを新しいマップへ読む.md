# JSONバックアップを新しいマップへ読み込む

プレビューで対象を確認し、元マップを上書きせず画像を含む別マップを作れる。この結果を利用者が画面、再読込、または保存したファイルから確認できることを受け入れ条件とする。

## 操作前の状態

一覧または保存済みの編集画面で、合成のJSONと画像付きJSONを用意している。アプリは本人1人のローカル環境で動作し、同じマップは一つの編集画面で扱う。

## ユーザーの操作

1. ファイルを選び、読込プレビューのマップ名・ノード数・画像数を確認する。
2. 「新しいマップとして読み込む」を押す。
3. 新旧マップを開き、保存・再読込後の内容を比較する。

## 期待する結果

- 新しいマップのIDとノード・画像IDを割り当て、元マップは変えない。
- 本文・順序・書式・メモ・画像が同じ意味の内容として復元される。
- 画像なしの旧形式JSONも読み続けられる。

## 失敗・取消・境界で守ること

- 100MiBを超える画像付きJSON、通常文書10MiB超、破損、循環、不正ID、未知版、画像欠落・不正Base64・寸法矛盾は理由付きで拒否する。
- 拒否時に一覧へ途中マップを増やさず、元マップも変えない。
- 現在の未保存内容や未完成リンクがある場合、確認なしに読み込みへ切り替えない。

## 確認方法と現在の状態

新規ID、画像復元、不正拒否、原子性、未完成入力保護の試験がある。対応する試験は[e2e/node-images.spec.ts](../../tests/e2e/node-images.spec.ts)、[e2e/editor.spec.ts](../../tests/e2e/editor.spec.ts)、[e2e/workflow-ux.spec.ts](../../tests/e2e/workflow-ux.spec.ts)、[io.test.ts](../../tests/io.test.ts)、[images-api.test.ts](../../tests/images-api.test.ts)にある。統合後の本番ビルド、Unit/API38試験、Chrome35試験は成功した。以下の未確認範囲を含め、すべての受け入れ条件が合格したと扱うものではない。

最大件数・最大深さ・最大ファイルを同時に使う画面操作は未網羅。試験定義があることを、このファイルの全条件が合格したという意味にはしない。実行日時と結果は[検証記録](../verification-results.md)へ残す。
