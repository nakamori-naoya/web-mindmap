# 全マップのバックアップを作る

アプリ稼働中でも、全マップと画像を一緒に復元できるバックアップを作れる。この結果を利用者が画面、再読込、または保存したファイルから確認できることを受け入れ条件とする。

## 操作前の状態

専用環境で複数のマップ、メモ、画像を保存している。バックアップ先に書き込み余裕がある。アプリは本人1人のローカル環境で動作し、同じマップは一つの編集画面で扱う。

## ユーザーの操作

1. 案内されたバックアップ操作を実行する。
2. 作成完了と出力先を確認する。
3. そのバックアップを専用の停止済み環境へ復元し、内容を比較する。

## 期待する結果

- 書き込み中のDBを単純コピーせず、整合した一つのDBコピーを作る。
- 全マップ、順序、メモ、書式、画像本体を同じ保存時点として保全する。
- 利用日の初回保存では日次バックアップを作り、日次分は直近7日分を保持する。

## 失敗・取消・境界で守ること

- バックアップ先障害を成功表示せず、正常な保存文書を破壊しない。
- JSONの一マップ出力と、全マップ・画像・保存版を含むDBバックアップを区別する。
- バックアップをGitや公開ディレクトリへ含めない。

## 確認方法と現在の状態

稼働中バックアップ、日次保持、障害、画像BLOBを含む実リストアを確認する試験がある。対応する試験は[storage.test.ts](../../tests/storage.test.ts)、[images-api.test.ts](../../tests/images-api.test.ts)にある。統合後の本番ビルド、Unit/API38試験、Chrome35試験は成功した。以下の未確認範囲を含め、すべての受け入れ条件が合格したと扱うものではない。

ディスク故障そのもの、別ディスク運用、合計64MiB上限に達した全マップの所要時間は未測定。試験定義があることを、このファイルの全条件が合格したという意味にはしない。実行日時と結果は[検証記録](../verification-results.md)へ残す。
