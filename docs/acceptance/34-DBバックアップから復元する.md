# 停止後にバックアップから全マップを復元する

現状を退避し、検査済みのバックアップから本文と画像をまとめて再開できる。この結果を利用者が画面、再読込、または保存したファイルから確認できることを受け入れ条件とする。

## 操作前の状態

実利用環境と分けた試験環境に、内容が異なる現状DBと復元元バックアップを用意している。アプリは本人1人のローカル環境で動作し、同じマップは一つの編集画面で扱う。

## ユーザーの操作

1. サーバーを正常停止する。
2. 現状DBを退避する復元操作を実行する。
3. 検査成功後に再起動し、全マップ・メモ・順序・画像を比較する。

## 期待する結果

- 復元前のDBを退避し、復元元と復元後の整合性を確認する。
- 復元元の全マップと画像本体が再起動後に表示される。
- 画像なしの旧形式バックアップも読める。

## 失敗・取消・境界で守ること

- サーバー稼働中の復元を拒否し、同じデータを二つの処理で変更しない。
- 破損DB、欠けた画像、不一致の画像ハッシュ、未知の新形式は拒否し、正常な現状DBを置き換えない。
- 失敗時に画像だけ、本文だけの途中状態で再開しない。

## 確認方法と現在の状態

停止・退避・実復元、起動中拒否、画像破損、旧形式互換を確認する試験がある。対応する試験は[storage.test.ts](../../tests/storage.test.ts)、[images-api.test.ts](../../tests/images-api.test.ts)にある。統合後の本番ビルド、Unit/API38試験、Chrome35試験は成功した。以下の未確認範囲を含め、すべての受け入れ条件が合格したと扱うものではない。

あらゆる復元中断タイミング、外部ストレージ故障との組合せは未網羅。試験定義があることを、このファイルの全条件が合格したという意味にはしない。実行日時と結果は[検証記録](../verification-results.md)へ残す。
