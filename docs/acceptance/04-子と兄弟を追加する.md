# 子と兄弟のトピックを追加する

選択中の位置を基準に、子と前後の兄弟を意図した順序へ追加できる。この結果を利用者が画面、再読込、または保存したファイルから確認できることを受け入れ条件とする。

## 操作前の状態

中心「Redis」と、その子「レプリケーション」がある編集画面でトピックを選択している。アプリは本人1人のローカル環境で動作し、同じマップは一つの編集画面で扱う。

## ユーザーの操作

1. 選択したトピックでTabまたは「子トピックを追加」を実行する。
2. 新しい本文を入力して確定し、Enterまたは「次の兄弟トピックを追加」を実行する。
3. 中心以外でShift+Enterまたは「前に追加」を実行し、追加位置を確認する。

## 期待する結果

- 子は選択トピックの末尾の子へ、次の兄弟は直後へ、前の兄弟は直前へ入る。
- 追加したトピックが選択され、そのまま本文を入力できる。
- 中心でのEnterは中心の子を追加し、中心に兄弟を作らない。

## 失敗・取消・境界で守ること

- 新規本文を空のまま確定すると「トピック」になる。
- 新規作成をEscapeで取り消すと、その新規トピック自体が消える。入力後の取消でも空ノードを残さない。
- 2000文字を超えた編集中の本文を確定できないときは、追加を続行せずドラフトと理由を残す。

## 確認方法と現在の状態

Tab・Enter追加、空新規確定、入力済み新規取消、文字数超過時の追加拒否を確認する試験がある。対応する試験は[e2e/editor.spec.ts](../../tests/e2e/editor.spec.ts)、[e2e/workflow-ux.spec.ts](../../tests/e2e/workflow-ux.spec.ts)、[domain.test.ts](../../tests/domain.test.ts)にある。統合後の本番ビルド、Unit/API38試験、Chrome35試験は成功した。以下の未確認範囲を含め、すべての受け入れ条件が合格したと扱うものではない。

前の兄弟追加の画面操作全経路と、選択なしでのキー操作は追加確認が必要。試験定義があることを、このファイルの全条件が合格したという意味にはしない。実行日時と結果は[検証記録](../verification-results.md)へ残す。
