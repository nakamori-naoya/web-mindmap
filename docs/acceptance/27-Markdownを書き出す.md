# マップをMarkdownへ書き出す

失われる情報を理解してから、本文の階層をMarkdownとして保存できる。この結果を利用者が画面、再読込、または保存したファイルから確認できることを受け入れ条件とする。

## 操作前の状態

画像、書式、メモ、リンクのあるマップを開いている。アプリは本人1人のローカル環境で動作し、同じマップは一つの編集画面で扱う。

## ユーザーの操作

1. Markdownの書き出しを選ぶ。
2. 保持できない情報の確認で取消す試行と、続行する試行を分ける。
3. 保存したMarkdownを新しいマップとして読み、本文の階層を確認する。

## 期待する結果

- 画像・枝色・文字サイズ・リンクなどを完全保持しないことを出力前に案内する。
- 続行した場合は本文の親子順序を見出し・箇条書きで表し、メモを文字として残す。
- 完全な保全にはJSONを使うと分かる。

## 失敗・取消・境界で守ること

- 取消した場合はファイルを完成扱いにせず、元マップも変えない。
- Markdownから画像の元ファイルを参照したり、ローカルパスを出力したりしない。

## 確認方法と現在の状態

Markdown変換と、探索評価における書出し・再読込の記録がある。対応する試験は[io.test.ts](../../tests/io.test.ts)、[e2e/editor.spec.ts](../../tests/e2e/editor.spec.ts)にある。統合後の本番ビルド、Unit/API38試験、Chrome35試験は成功した。以下の未確認範囲を含め、すべての受け入れ条件が合格したと扱うものではない。

画像除外警告の確認取消を含む全ブラウザ経路は自動試験で未網羅。試験定義があることを、このファイルの全条件が合格したという意味にはしない。実行日時と結果は[検証記録](../verification-results.md)へ残す。
