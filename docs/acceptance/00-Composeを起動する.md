# Docker Composeでアプリを起動する

案内されたDocker Composeの操作でアプリを起動し、ローカルブラウザからマップを開ける。コンテナを再作成しても、利用者が保存した本文と画像が残ることを受け入れ条件とする。

## 操作前の状態

Docker DesktopまたはOrbStackとDocker Composeが動作するローカルマシンを用意する。初回のイメージと依存取得にはネットワークが必要である。再起動・異常終了の試験は、利用中の保存先と分けた専用データを用いる。

## ユーザーの操作

1. 起動手順に従い、Docker Composeでビルドと起動を行う。
2. ブラウザで `http://127.0.0.1:4173` を開き、一覧と編集画面へ進む。
3. 専用マップへ本文と画像を保存し、コンテナを正常停止・再起動する。
4. 専用環境でコンテナを異常終了させ、同じ保存先で再起動する。

## 期待する結果

- ビルドした実行用イメージだけで起動し、必要なモジュールや画像処理依存の欠落で停止しない。
- 稼働確認が正常となり、ブラウザでマップを作成・閲覧・編集できる。
- ホストの公開先は127.0.0.1に限定し、外部公開を前提にしない。
- 正常再起動と異常終了後の再起動で、最後に保存した本文・順序・メモ・画像を再表示する。
- コンテナの再作成だけで、永続保存したデータを削除しない。

## 失敗・取消・境界で守ること

- ポートの競合、保存先への書込み不可、起動失敗を、利用可能になったように表示・報告しない。
- 既存の正常なDBとバックアップを、環境準備のために自動削除しない。
- 異常終了で残った古い起動記録や再利用されたプロセス番号を理由に、再起動を拒否し続けない。
- 初回ビルドのネットワーク利用と、起動済みアプリが本文・画像を第三者へ送ることを混同しない。

## 確認方法と現在の状態

本番ビルド、専用Compose環境での画像保存・再起動・バックアップ復元が成功した。ネットワークを持たない実行用コンテナの内部で稼働確認も成功した。実行用イメージのモジュール欠落は修正後に独立再試験され、指摘が取り下げられた。

自動検査の定義は[CI](../../.github/workflows/check.yml)と[Compose実検証](../../scripts/verify-compose.ts)、運用手順は[README](../../README.md)にある。初期の実行証拠は[Compose検証記録](../compose-verification.json)、統合後の確認結果は[検証記録](../verification-results.md)を参照する。

Docker DesktopとOrbStackの全バージョン、Windows上のDocker、保存ディスクの実故障は未確認である。この確認を、全環境での起動保証としない。
