# Markdownから新しいマップを作る

文章の見出しと箇条書きの階層を、確認後に編集可能な木へ変換できる。この結果を利用者が画面、再読込、または保存したファイルから確認できることを受け入れ条件とする。

## 操作前の状態

見出し・入れ子箇条書き・段落・コードを含む合成Markdownを用意し、一覧を開いている。アプリは本人1人のローカル環境で動作し、同じマップは一つの編集画面で扱う。

## ユーザーの操作

1. Markdownファイルを選ぶ。
2. プレビューを確認し、新しいマップとして読み込む。
3. 中心と枝が見えること、段落とコードがメモへ残ることを確認する。

## 期待する結果

- 最初のH1が中心となり、後の見出しは直前の浅い見出しの子になる。
- 見出しレベルが飛んでも空の中間トピックを作らず、箇条書きの入れ子を保つ。
- 見出しなしはファイル名を中心とし、2つ目以降のH1は中心直下へ置く。
- 読込直後に中心が画面内に収まり、全体表示を押さないと操作できない状態にしない。

## 失敗・取消・境界で守ること

- 空ファイルと10MiB超は拒否し、既存マップを無言で置き換えない。
- HTMLやコードブロックを実行せず、文字としてメモに残す。
- 現在の未完成入力がある場合は、その内容を保護する。

一覧からの初期配置、Markdown規則、コード保持、未完成入力保護を確認する試験がある。対応する試験は[e2e/workflow-ux.spec.ts](../../tests/e2e/workflow-ux.spec.ts)、[io.test.ts](../../tests/io.test.ts)にある。統合後の本番ビルド、Unit/API38試験、Chrome35試験は成功した。以下の未確認範囲を含め、すべての受け入れ条件が合格したと扱うものではない。
