# ユーザー操作ごとの受け入れ条件

確認したい操作のファイルを一つ開けば、操作前の状態、ユーザーが行う操作、期待する結果、失敗・取消の条件を確認できる。各ファイルは受け入れ条件の定義であり、全条件の合格宣言ではない。自動試験の範囲と未確認の手動条件も、その操作のファイルに記載する。

確認に使うアプリは、本人1人がローカルで使用するマインドマップである。破壊的な確認と障害の再現は専用の試験用マップ・保存先で行い、利用中のマップを使わない。

## 条件と実施結果を分ける

各操作の条件は、利用者が何を確認できればよいかを定める。自動試験の定義が存在しても、実機IMEや実タッチ端末、すべての境界が確認済みとは限らない。画像機能統合後の本番ビルド、Unit/API38試験、Chrome35試験は成功している。画像関連の独立指摘3件も修正後に再確認された。これらの結果を、各操作に残る未確認条件への合格判定へ広げない。

従来の実施結果は[検証記録](verification-results.md)へ内容を保全した。以後の実行結果も検証記録へ追記し、条件そのものと混ぜない。画像の容量・保存形式・元パスを保持しない方針は[画像の保存設計](node-images.md)を参照する。
